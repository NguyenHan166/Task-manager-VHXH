# BE-00-03 — REST, DTO, lỗi và Socket.IO

**Nguồn chuẩn để sinh client:** [`openapi.v1.json`](./openapi.v1.json) (`info.version=1.0.0`, base URL `/api`). Bảng dưới là chỉ mục FE; nếu mô tả cũ trong PRD §10, handoff §2 hoặc API mapping khác OpenAPI, dùng các quyết định D-01–D-11 và tài liệu này. P0 được thực thi qua Phase 02–08; operation `x-release-phase: P1` chỉ bật khi Phase 09 hoàn tất.

## Quy ước chung

- JSON thành công luôn `{ "data": T }`; danh sách là `{ "data": { "items": T[], "total", "page", "pageSize" } }`. `POST` tạo mới trả `201`, lệnh khác `200`. Xuất CSV/XLSX là ngoại lệ nhị phân, chỉ kèm header `Content-Disposition`.
- Lỗi luôn `{ "error": { "code", "message", "fieldErrors?" } }`. `400 VALIDATION` cho body/query sai; `401 UNAUTHORIZED` thiếu/hết phiên; `403 FORBIDDEN` sai vai trò hoặc quan hệ trên bản ghi đã nhìn thấy; `404 NOT_FOUND` cho ID không tồn tại **hoặc bản ghi không được đọc**; `409 CONFLICT` cho state/version đổi, request PENDING trùng hoặc command lặp không có idempotency key; `429 RATE_LIMITED` khi vượt giới hạn. Không dùng 422. Không nhận tham số actor từ client.
- `page` bắt đầu 1, mặc định 1; `pageSize` mặc định 10, tối đa 100. `sortBy` gồm `DUE_AT`, `UPDATED_AT`, `PRIORITY`, `CREATED_AT`; `sortDirection` mặc định DESC. Thứ tự bằng nhau dùng `id` làm tie-breaker; hạn NULL luôn cuối. `isOverdue=true` là `dueAt < now` và status không phải DRAFT/DONE/CANCELLED. ACL áp dụng trước đếm `total`, filter, export, thống kê.
- FE coi `ALL` ở ô lọc là giá trị giao diện. `HttpRepository` bỏ query parameter `projectId`/`primaryAssigneeId` khi người dùng chọn `ALL`; với `type`/`status`/`priority`, có thể bỏ parameter hoặc gửi `ALL` như OpenAPI.
- UUID do BE sinh. Tất cả thời điểm JSON là ISO 8601 UTC kết thúc `Z`. Body `dueAt` là thời điểm UTC; khi FE chỉ có ngày, gửi `dueDate: YYYY-MM-DD` thay `dueAt`, BE ghép `defaultDueHour` trong `Asia/Ho_Chi_Minh`. Hai trường loại trừ nhau. `dueAt` của nhiệm vụ đã phát hành chỉ đổi qua `/adjust`.
- Access token 15 phút trong `Authorization: Bearer`; refresh cookie `HttpOnly; Secure; SameSite=Lax; Path=/api/auth` sống 7 ngày, xoay vòng. `/auth/refresh` dùng refresh cookie; logout và logout-all xác thực bằng Bearer rồi thu hồi phiên và xóa cookie. Browser gửi credentials để nhận/xóa cookie. Không gửi refresh token trong JSON hoặc localStorage.
- Login tối đa 5 lần/phút theo cặp IP và SHA-256 của email đã chuẩn hóa; giới hạn API chung là 60 lần/phút. Tài khoản không tồn tại và LOCKED không có thông báo đăng nhập riêng.
- Password mới tối thiểu 12 ký tự; mọi password tối đa 72 byte UTF-8 để khớp giới hạn đầu vào bcrypt.
- DTO có `additionalProperties: false` khi có body. BE tự gán ID, code, createdById, actorId, submittedById, decidedById, completedAt, approvedById, objectKey và status. Mọi command đổi nhiều bảng chạy trong transaction; event/notification bền trước khi phát Socket.

## Socket.IO và event bền

REST/DB là nguồn sự thật. Socket handshake dùng access token và chỉ join room server tính từ ACL: `user:{id}`, `task:{id}` (nếu còn quyền), `chat:{id}` (P1). Client không được tự join ID tùy ý. Khi reconnect, FE gọi `GET /notifications?after=<cursor>`; Phase 09 lấy chat bằng cursor `beforeId`. Payload Socket có `eventId`, `occurredAt`, `entityId` và ID hoặc bản rút gọn; client de-duplicate theo `eventId` rồi refetch entity qua REST.

| Hướng           | Event                            | Phase | Điều kiện phát/nhận                                                                       |
| --------------- | -------------------------------- | ----- | ----------------------------------------------------------------------------------------- |
| Server → client | `notification:new`               | P0    | Sau commit notification, chỉ `user:{recipientId}`; không gửi nội dung task khi ACL đã đổi |
| Server → client | `task:updated`                   | P0    | Sau commit TaskEvent, chỉ room task còn quyền; payload ID/version, không gửi toàn bộ task |
| Server → client | `message:new`, `message:updated` | P1    | Sau commit message, chỉ member room chat                                                  |
| Client → server | `room:join`, `room:leave`        | P0/P1 | Server kiểm tra lại user/task/chat membership trên mỗi join; lỗi không tạo room           |

Event nghiệp vụ bền là `TaskEvent` (`CREATED`, `DETAILS_UPDATED`, `COMMENT_ADDED`, `PUBLISHED`, `STARTED`, `PROGRESS_UPDATED`, `BLOCKED`, `UNBLOCKED`, `SUBMITTED`, `SUBMISSION_WITHDRAWN`, `APPROVED`, `RETURNED`, `DEADLINE_CHANGED`, `ASSIGNEE_CHANGED`, `CANCELLED`, `REOPENED`; P1 thêm request/invitation/recurrence/type). Notification type theo `data-contract.ts`; email/Zalo P2.
